## 앱과 데모

자유 시연은 `/` → **자유형식** → **새 프로젝트 시작**이다. 좁은 화면에서는 **메뉴**를 연다. 같은 앱의 **시나리오**는 사람 입력만 재생하며 실제 서버·원장과 설정한 PM/Agent를 사용한다.

`/demo/pm-coordination`(PM 조율), `/demo/marketing-campaign`(마케팅 캠페인), `/demo/design-to-code`(디자인→개발 협업)는 별도 스크립트 시연이다. 세 경로 모두 실제 모델·프로젝트 API·Slack·미팅·메일 서비스를 실행하지 않는다.

데모 소스·이미지·설명은 `app/demo/scripted/`, 실제 앱을 사용하는 관찰 도구와 안내는 `app/demo/runtime/`에 둔다. 제품 UI·API와 PM·원장·저장소는 `app/apps/web` 및 `app/packages`에 유지한다.

## 정리한 범위

구현되지 않은 Product State 설계와 관련 발표, 역할을 다한 초기 PM 구현 계획, 그 설계를 전제로 한 Argo 적용·비교 문서는 제거했다. 날짜별 과거 QA·스크린샷·벤치마크 증거도 현재 트리에서 제거했다. 해당 자료를 현재 규칙이나 품질 근거로 연결하지 않는다.

사용자 결정은 결정 기록에 남기고, 현재 동작은 코드와 연결한다. “기능이 존재한다”, “자동 검사가 통과한다”, “실제 팀의 조율 부담이 줄었다”를 서로 다른 주장으로 다룬다.

## 추가 문서 제안

**핵심 협업 흐름의 검증 계획** 한 문서를 우선 제안한다. 개인 Agent와의 작업→명시적 공유→필요한 검토·보완→후속 인계를 실제 팀에서 반복 관찰하고, 기존 방식의 재설명·담당자 탐색·인계 재작업 횟수와 시간을 기준선으로 비교하는 내용이다. 품질·필수 검토·공유 통제의 유지와 최신 결정·버전 반영도 함께 관찰한다. 성공 목표치와 참여 팀은 아직 결정하지 않았으며 새 설계 명세로 확정하지 않는다.
