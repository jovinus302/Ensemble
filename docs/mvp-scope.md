# Ensemble MVP 범위

## 증명하려는 경험

여러 사람과 여러 Agent가 일하는 다양한 협업에서 PM Agent가 흩어진 맥락을 목표 아래 연결하고 다음 행동을 조율한다. 우측 보조 뷰는 연결의 출처와 반영 여부를 확인하는 수단이다. [제품 의도](../intent.md)가 기준이다.

## 제품 역할과 이번 시연의 관계

| PM Agent의 역할 | 이번 시연에서 관찰할 부분 | 실제 제품에서 별도 확인할 부분 |
|---|---|---|
| Context Aggregator | 개발·디자인·Slack·미팅의 출처 연결 | 실제 이메일·문서·도구·Agent 연동과 권한 |
| Goal/State Manager | 로그인 목표, 담당, 결정, 반영 대기 | 여러 프로젝트의 최신성·의존성 관리 |
| Coordinator | 서로 필요한 산출물과 미팅 결정 전달 | 실제 담당자·Agent에 전달하고 수신 확인 |
| Proactive PM | 미팅 결정과 기존 결과의 차이 표시 | 실제 지연·충돌·누락 감지의 정확성과 개입 시점 |
| Action Agent | 두 작업의 후속 반영을 안내하는 예시 | 실제 메시지·미팅·태스크 생성과 실패 복구 |
| Organizational Memory | 결정 이유·출처·현재 버전 표시 | 장기 보존·검색·접근 통제 |

## 새 데모의 범위

- 개발 Agent의 이메일 로그인 구현 예시와 디자인 Agent의 로그인 화면 작업 예시.
- 각 작업 환경의 PM Agent, Slack의 범위 합의와 미팅 결정 연결.
- 독립적인 결과 연결, 결정에 따른 양쪽 후속 반영과 버전 구분.
- 보조 뷰에서 원본 작업으로 돌아가기, 산출물 확인, 초기화와 모바일 접근.

데모는 작성된 작업 예시를 사용한다. 실제 로그인 서비스·인증·외부 도구 연결·Agent 실행·동기화·영속 저장은 제공하지 않는다. 고정 대사를 시간순으로 자동 재생하는 엔진도 사용하지 않는다.

## 실제 제품 구현과의 차이

| 기존 구현 | 새 방향에서의 위치 | 아직 필요한 것 |
|---|---|---|
| 프로젝트 채널과 작업 패널 | 내부 관리 앱 | 기존 도구 안의 PM 접점 |
| 이벤트 원장과 SQLite | 내부 기록 수단 | 외부 원본 식별·버전·수정·삭제 연결 |
| PM 계획·조율·인계 | 재사용 가능한 조율 기능 | 여러 환경의 출처와 권한을 고려한 연결 |
| Codex·Claude 세션과 provider | 앱이 관리하는 실행 연결 | 사용자의 기존 Agent 세션과 안전한 접점 |
| 검토·권한·결정 요청 | 보존해야 할 실행 경계 | 실제 조직 인증·공유 권한과의 결합 |

기존 앱의 코드 구조나 상태 모델을 제품의 정체성으로 승격하지 않는다. 새 데모가 실제 도구 간 연동을 구현했다는 뜻도 아니다. 내부 계약은 [작업 모델](work-model.md), 실행 선택은 [아키텍처](mvp-architecture.md)를 따른다.

## 유지할 조건

공유한 결과만 허용 범위 안에서 연결한다. 제안과 확정 결정을 구분하며, 산출물 생성·결정 전달·완료를 혼동하지 않는다. 개인 Agent와의 직접 작업을 유지하고, 필요한 사람 검토와 실행 권한을 우회하지 않는다. 기존 제품의 중복 실행 방지, 프로젝트 격리와 오래된 결과 차단도 보존한다.

## 확인할 제품 효과

실제 팀에서 기존 방식과 비교해 재설명·담당자 탐색·인계 시간 및 누락 횟수를 기록한다. 변경된 결정의 양쪽 반영, 출처·버전 정확성, 검토와 공유 통제도 함께 확인한다. 메시지 수나 데모 검사 통과를 효과의 증거로 대신하지 않는다. 첫 외부 연동 도구, 인증·보존 정책, 대상 팀과 성공 수치는 열린 결정이다.
