현행 근거: [웹 런타임](../app/apps/web/lib/runtime.ts), [PM 조정](../app/packages/orchestrator/src/coordination.ts), [검증](../app/packages/orchestrator/src/validation.ts), [하루 요약](../app/packages/orchestrator/src/digest.ts), [v4 증거](../app/packages/benchmark/evidence/paired-validation-v4/README.md). 이 문서 갱신은 모델 호출이나 새 기능 검증 실행을 포함하지 않는다.

## 핵심 기능 6개

| # | 기능 | 포함 | 제외 (나중에) |
|---|---|---|---|
| F1 | Slack형 채널 | 채널 1개, 스레드, 첨부. 멤버: 사람 2명(화면에서 사용자 전환), 실행 Agent 2개, PM | 실제 인증, DM, 여러 채널, 손님 권한 |
| F2 | 실행 Agent = Codex 세션 | Codex app-server로 세션 기동, 작업 지시, 진행 중 변경 주입(`turn/steer`), 확인 응답·결과 회수, 채널 게시. Agent당 한 번에 한 턴 | Claude Code 연결(같은 연결 계약으로 두 번째), 재연결 고도화 |
| F3 | 인계와 맥락 연결 | 결과가 올라오면 PM이 인계 조건을 판단(`checked`). 충족이면 다음 담당을 지시 없이 시작, 부족하면 무엇이 빠졌는지 요청. 정해진 칸의 맥락 전달. 사람→Agent, Agent→사람(요약·할 일), Agent 질문 → 사람 → 원래 작업 | 검증 승인 카드, `passed` 판정, 목표 달성 승인, `computeGap` |
| F4 | 대화 속 조율 | 사람들은 평소처럼 채팅한다. PM은 계속 듣고 `pm-principles.md`에 따라 필요할 때만 한두 문장으로 말한다. 결론이 나면 "정리하면…"으로 확인하고 계획 vN+1로 반영, 바뀐 사람과 Agent에게만 알리고 진행 중인 Agent에는 변경을 주입한다. 맡겨진 범위 밖이면 그 자리에서 권한 있는 사람에게 묻는다. 조율 스레드는 강제하지 않는다 | 여러 조율의 동시 병합, 정교한 되돌리기 |
| F5 | 로드맵 카드와 기한 예측 | 채널 고정 카드: 계획 버전, 누가 무엇을, 막힌 곳과 풀 사람, 예상 종료와 기한 비교, 부족 시간. 코드 계산: 사람별 주간 가용 시간 × 작업 추정(최소~최대) × 선후 관계. 배정 추천은 역할 적합과 여유 시간 | 캘린더 연동, 최적 배정, 주기적 요약 발행 |
| F6 | 시나리오·자유형식 모드 | 같은 엔진. 시나리오 모드는 사람 발언만 재생하고 PM과 Agent는 실제로 동작. PM이 끼어드는 시점은 대본에 정하지 않는다 | 자동 지표 대시보드 |

## 줄어도 지키는 규칙
- 작업 기록(코드의 `ledger`)이 유일한 정본이다. 현재 상태·화면·카드는 기록에서 계산한다.
- 확인 한 번에 작업 시작 한 번. Agent 하나당 한 번에 한 턴.
- PM 자동 행동에 상한이 있고, 닿으면 사람에게 알린다.
- 계획은 버전으로 남는다. 옛 버전 기준 결과물은 표시하고 인계하지 않는다.
- 실행 Agent는 작업 기록에 직접 쓰지 못한다. 결과·첨부·질문·변경 확인만 제출한다.
- PM의 모든 발언은 `pm-principles.md`의 세 질문 답과 함께 기록한다.

## 시연 3장면
1. 시작: "2주 안에 고객 반응 확인" → PM이 팀과 계획 v1 제안(가용 시간 반영) → 조사 Agent와 인터뷰(사람) 병렬 시작.
2. 인계: 디자이너가 흐름 초안 첨부 → PM 판단 → 부족하면 보완 요청 → 보완되면 아무도 "시작해"라고 하지 않았는데 프로토타입 Agent가 초안 기준으로 시작.
3. 조율: 제작 도중 사람들의 자연스러운 대화("목요일 휴가", "결제는 빼자") → PM이 필요한 순간에만 기한 영향을 말하고 결론을 정리 → 계획 v2 → 바뀐 사람에게 알림, 프로토타입 Agent에 변경 주입 → 로드맵 카드 갱신.

## 단계
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M1 | 작업 기록, 계획 버전, 상태 전이, 기한 예측(순수 로직) | 단위 테스트: 중복 시작 없음, 가용 시간 감소 시 예측 지연, 입력 없으면 날짜 없음 |
| M2 | Codex 세션 연결(F2) | 실제 Codex로 기동 → 진행 중 변경 주입 → 확인 응답 → 결과 회수 재현 |
| M3 | PM 루프(F3·F4) | 장면 2·3을 코드 수준에서 재현, 발언·침묵의 근거가 기록됨 |
| M4 | 웹 채널·로드맵 카드(F1·F5), 두 모드(F6) | 브라우저에서 3장면 시연 |

## 확정 결정 (2026-09-28, 사용자: "추천안대로 진행해")
- 검증 승인 카드·`passed`·목표 승인·`computeGap`은 이번에 뺀다. intent의 "완료 보고가 아니라 결과물을 본다"는 F3의 인계 판단으로 지킨다.
- 실행 Agent는 Codex 세션부터, 사용자의 Codex 계정과 지정 작업 폴더로 연결한다. PM은 사내 proxy를 유지한다.
- PM 위임: 초기 계획에서 맡긴 범위 안의 명확한 결론은 PM이 즉시 반영하고, 수정은 새 버전으로 남긴다. 위임 밖 변경과 사람의 새 시간 약속은 해당 사람에게 묻는다. 목표·기한 변경은 항상 결정권자가 정한다.
- 가용 시간은 사람별 주간 시간으로 입력하고 7일에 균등 환산한다. 작업 추정은 최소~최대 시간. PM 자동 행동은 명시적 재개 사이 12회에서 멈추고 한 번 알린다.
