# v4-pm 스타일 프레임 실행·검토 기록

2026-09-28. PM 플랜 `36f6d7c`, v4 승인 기준 `e1e77bf`. 사전 명제 `6a5db2a`, 스토리보드 `c83886b`, 사용자 추가 피드백 명제 `fcb1cfa`. 아래 구현 검토는 이 문서 작성 시점의 **사후 검토**이며, 당시 선행 명제와 이후 추가 결정을 구분한다.

## 1. 처음 만든 결과와 환경 복구

- 원문 5개는 다른 브랜치에서 `git show`로 읽었다. 체크아웃·병합하지 않았다.
- 최초 보드는 기존 v4의 Stage·부상 카드·콜아웃·Z 투영을 사용했다. 새 보드와 메시지만 v4pm에 격리했다. B1–B6 여섯 장과 O1·O2를 렌더했다.
- PowerShell의 `npm.ps1` 실행 정책 오류는 `npm.cmd`로 실행해 해결했다. 의존성 설치와 브라우저 기동의 `spawn EPERM`은 승인된 샌드박스 밖 실행으로 해결했다. `npm ci` 완료, 패키지 잠금 파일 변경 없음.
- PowerShell의 stderr 리디렉션이 Chromium 로그를 여러 줄로 나누고 NativeCommandError로 기록했다. 렌더 성공 여부를 문자열로 추측하지 않도록 `render-check.mjs`에서 CLI의 실제 종료 코드와 UTF-8 로그를 직접 수집했다.
- 첫 수집기의 접두어 길이가 한 글자 틀려 JSON 파싱에 실패했다. 상수 길이를 문자열의 `.length`로 읽도록 고쳐 같은 측정값을 다시 수집했다. 렌더 장면의 정책이나 기준을 낮추지 않았다.

## 2. 사용자 요구 추가 — 원래 명제와 구분

첫 구현 중 사용자가 세 가지를 추가했다. (1) 그레인 제거 (2) 착지 직후 PM 답장과 팀원 목록 「지휘 중」 (3) 오프닝 세 번째 카피 중앙 약 2초 유지. 변경 구현 전에 명제·스토리보드를 `fcb1cfa`로 커밋했다.

- 그레인: `StageV4`를 수정하지 않고 `StageV4PM`에서 Noise 레이어를 제외했다. 배경, 벽 그림자, 보드 리그의 공간 방식은 유지했다.
- 답장: O2의 김도윤 목표 발언 아래 PM이 이번 주 가용 시간을 묻는다. 입력이 있어야 다음 배정이 달라지므로 PM 발언 원칙 1과 근거 원칙에 부합한다. 사람 답변 전에는 「답변 대기」이며 일정 확정을 약속하지 않는다.
- 중앙 카피: 초기 O2는 상단 헤드라인이므로 중앙 홀드의 증거가 될 수 없었다. 보충 명제에 기록한 뒤 중앙 타입 장면 OH를 추가했다. 120–180f는 OH, 180–210f는 착지, 210–222f는 답장 등장으로 배정했다. 전체 57초 유지, 팀 소개를 5초에서 4초로 조정했다.

이 요구 추가는 결함을 숨기기 위한 기준 완화가 아니다. 이후 결함 수정 라운드는 아래처럼 종류를 하나로 제한했다.

## 6. 재현

`motion-remotion/`에서 실행한다. Windows에서는 `npx.cmd`를 쓴다. props 파일은 UTF-8 JSON이다.

```powershell
npx.cmd tsc --noEmit
npx.cmd remotion still src/index.ts StyleFrameV4PM review/v4-pm/B6.png --props=review/v4-pm/props/B6.json
node review/v4-pm/render-check.mjs final
node review/v4-pm/render-check.mjs debug
node review/v4-pm/render-check.mjs regression
```

`final`은 대표 9장, `debug`는 기능 비트 부상 전후 12장, `regression`은 기존 v4 4장이다. 특정 스틸만 다시 확인하려면 `node review/v4-pm/render-check.mjs final OH`처럼 ID를 붙인다. 원시 로그와 중복 v4 PNG는 저장소에서 제외하며, 검토에 필요한 JSON·최종 PNG·투영 디버그 PNG·props·재현 스크립트는 함께 보존한다.
