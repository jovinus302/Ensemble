## 1. 확정된 의도

- 시청자가 PM을 단순한 순차 배정기가 아니라, 사람과 Agent 사이의 인계와 대화 속 변경을 이어 주는 팀원으로 이해해야 한다.
- 사용자 요청 범위는 한국어 변경 명제 → 스토리보드 → 바뀐 비트의 스타일 프레임이다. 변경 명제를 먼저 커밋하고 단계마다 커밋한다. 전체 `PitchV4PM`은 만들지 않는다.
- 승인된 정면 2.5D 룩, 오프닝 회전 한 번, 오프닝 세 문장과 클로징 문장은 보존한다.
- PM 제품 계획 자체는 고치지 않는다. 지정 작업 공간과 `jovinus302/pitch-v4-pm-plan` 브랜치에서 작업하고 origin에 push한다. PR은 만들지 않는다.

## 2. 이번 변경의 해석

**EXPERIMENT 가설:** 기존 여섯 비트 틀을 유지하되, 마지막 두 비트를 자연스러운 조율과 계획 v1→v2·전달 추적으로 교체하면, 57초 안에 자동 인계와 진행 중 변경을 함께 설명할 수 있다. 원래의 목표 점검·검증 장면을 억지로 남기는 안, PM이 매 발언마다 스레드를 여는 안은 채택하지 않는다.

최신 `mvp-scope.md`는 이전 `pm-agent-plan.md`를 좁힌다고 명시한다. 영상은 좁은 범위에 맞추되, 그 문서의 잠정 결정을 확정된 제품 결정이라고 쓰지 않는다. 아래 절 번호가 없는 원문에는 절 제목과 F 번호를 병기한다.

되돌아감은 입력 수정본과 이전 계획 결과 표시로만 다룬다. 정교한 되돌리기, 동시 조율 병합, CI·자동 검증, 다중 프로젝트, 일정 최적화, 두 실행 공급자 동시 지원은 화면에 넣지 않는다. 실행 세션은 Codex부터라는 F2 범위를 따른다. 모형 대화와 일정은 시연 예시임을 표시하고, 실제 효과 측정처럼 쓰지 않는다.

**가설 검토: SOUND.** PM 플랜의 새 범위와 직접 연결되고 기존 소스를 보존해 되돌리기 쉽다. 비트별 대표 스틸과 대사 표로 내용의 누락·과장을 검토할 수 있다. 스틸만으로 실제 조율·자동 실행·시간 흐름을 입증할 수는 없다. 승인 뒤 별도 모션 관찰이 필요하다.

## 4. 불변 조건

- `src/v3/**`, `src/v4/**` 수정 없음. 기존 v4 스틸 4장의 재렌더 SHA256 일치.
- `design-v4.md` §4 r2 그대로: 본문 화면 크기 ≥20px, 보조 ≥18px, 주인공 칩·배지 높이 ≥36px. 읽지 않는 회전 시작 O1만 크기 예외.
- 헤드라인과 UI 텍스트 겹침 없음. 콜아웃이 UI를 가리지 않고 지시선이 칩까지 연결. 부상 전후 앵커 오차 ≤1px. 투영에 Z 포함.
- 머무는 포즈는 (0,0,0)° 또는 오프닝 (0,−40,0)°. 중간 회전 체류는 모션 승인 뒤 검사한다.
- 헤드라인은 공백·영문·문장부호 포함 18자 이하. 오프닝 「Agent는 늘었는데 / 다음 일은 사람이 챙긴다 / 다음 일은 AI PM이 챙긴다」와 클로징 「다음 일은, PM이 챙긴다」 유지.
- 논리 좌표는 `px()` 사용. 부상 카드 자체의 불투명 표면과 그림자. 절대배치가 본문을 덮지 않는지 확인.
- 위임 범위 밖 결과 변경은 권한자의 명시적 결정, 사람의 시간은 당사자의 답변이 선행한다. 전달 성공·Agent 확인·결과 반영을 동일시하지 않는다.
- 목업을 실행 제품의 증거로 주장하지 않는다. 가짜 통계·로고·과장어 없음.
- 사용자 추가 피드백(r1): v4-pm 무대에서 `Noise`를 완전히 제외한다. v4 소스는 그대로 두고 무대를 v4pm에 복사한다.
- 착지 직후 김도윤의 목표 메시지 아래 PM이 가용 시간을 묻는 짧은 답장을 올리고, 팀원 목록 AI PM의 「지휘 중」 상태를 켠다. 이 발언은 다음 계획에 필요한 입력을 얻는 행동이며, 형식적인 맞장구가 아니다.
- 오프닝 세 번째 카피(③) 「다음 일은 AI PM이 챙긴다」는 중앙에서 약 2초 온전히 머문 뒤 다음 비트로 전환한다. 기능 비트 ③과 구분한다.

## 7. 미결정 사항

- `mvp-scope.md`의 검증·목표 승인 제외는 사용자 확인 대기인 잠정 결정이다. 영상은 이를 제공 기능으로 약속하지 않는 보수적인 범위를 택한다. 제품 결정의 확정은 이 작업에서 하지 않는다.
- 이전 계획 §2의 스레드 중심 조율과 최신 F4의 자연 대화·스레드 비강제가 다르다. 최신 원칙을 기준으로 스레드는 선택적 상세 보기로만 그린다.
- 가용 시간·추정 수치는 시연 예시다. 실제 엔진의 계산 정확도나 시간 절감 효과를 증명하지 않는다.
- 스타일 프레임과 비트 구성의 사용자 승인, 모션 제작·검증은 남는다. 실행 계정·한도·권한 정책 수치는 제품 플랜의 미결정으로 유지한다.

## 8. 카피

오프닝·클로징은 §4 원문을 사용한다. 비트는 ① 사람과 Agent, 한 채널에 ② 가용 시간을 보고 맡긴다 ③ 필요한 맥락을 이어 준다 ④ 아무도 '시작해'라고 안 했다 ⑤ 대화가 바뀌면, 계획도 ⑥ 바뀐 일을, 담당자에게. 구현에서 글자 수를 검사한다.

## 9. 통합 지점

승인된 `StageV4`, `HeroLift`, Z 투영, 콜아웃, 헤드라인, 토큰·폰트를 import한다. 보드의 채널·로드맵·메시지 내용은 `src/v4pm/`에 새로 둔다. v4 목업의 다중 채널·검증 패널을 감춘 채 재사용해 제품 약속이 남는 방식은 피한다.

r1 변경: `StageV4` 직접 사용 대신 같은 구조의 `StageV4PM`을 v4pm에 둔다. 배경·BoardRig·벽 그림자는 import하고 Noise 레이어만 제외한다. 이는 사용자 피드백으로 승인된 룩 조정이다.

## 10. 의도 이탈 지점

보존하기로 한 룩·카피·수치 기준의 이탈 제안은 없다. 기존 ⑤·⑥의 기능 약속 변경은 사용자가 요청한 PM 플랜 반영 범위다. 최신 MVP의 잠정 항목을 제품에서 확정하는 행위와 구분한다. r0 명제의 결과나 불변 조건을 약화해야 한다면 `PROPOSITION CHANGE`로 기록하고 사용자 확인을 받는다.
