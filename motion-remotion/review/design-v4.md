# v4 설계 노트 — 피치 영상 방향 재설계

2026-09-28. v3 스타일 프레임 8라운드 뒤 사용자가 두 가지를 지적했다. 오프닝 카피 "잇는 건 이제 PM"이 어색하고, 원근이 애매하다. 그리고 "v3 방향 전체를 처음부터 다시" 만들라고 지시했다. 원근은 "너가 제안", 카피는 "GPT와 의논"으로 위임받았다. 이 노트는 Codex Sol(gpt-6-astra, xhigh)의 설계 리뷰(판정 REVISE)를 반영한 r1이다.

v3 산출물(`storyboard-v3.md`, `review/spec-v3-architect.md`, SF r3–r8)과 v3 코드는 지우지 않고 바꾸지도 않는다. v4는 새 파일로 쌓는다.

변경 성격: **EXPERIMENT**. 원근 가설과 카피는 사용자가 보고 판정한다.

## 1. 확정된 의도

- 영상은 Ensemble 피치 영상이다. 보는 사람이 가져갈 믿음은 이것이다. "Agent가 늘어도 그 사이를 잇는 일은 아직 사람 몫이다. Ensemble에서는 AI PM이 배정·인계·판정을 잇는다." (`intent.md` §2–4)
- 오프닝 카피는 바꾼다. 사용자가 어색하다고 했다.
- 원근을 바꾼다. 지금의 rx 9–12°, ry 18–22°는 평면으로도 입체로도 읽히지 않는다.
- 범위는 v3 방향 전체다. 스토리보드, 카메라, 카피, 스타일 프레임이 모두 포함된다.
- 이미 확정된 결정은 유지한다.
  - Remotion과 CSS 3D를 쓴다. `@remotion/three`는 쓰지 않는다. 이유는 텍스트 선명도다 (`tech-memo-v3.md`).
  - 1920×1080, 30fps다.
  - 스틸 승인 전에는 모션을 만들지 않는다.
  - 한 라운드에 결함 한 종류만 고친다.
  - UI 토큰은 `DESIGN.md` 값을 쓰고, 영상 예외 규칙(`spec-v3-architect.md` §0)을 따른다.

## 2. 이번 변경의 해석

**선택한 해석.** "방향 전체"는 원근·카메라·구도, 카피, 스토리보드다. 보존하는 것은 제품 가치(`intent.md`)뿐이다.
- 비트 수와 순서, 목업 문구와 배치, 재질, 전체 연출은 모두 **재검토 대상**이다.
- 이번 실험의 출발점으로는 v3의 6비트와 `content.ts` 목업을 쓴다. 사용자의 지적이 원근과 카피에 있었고, 첫 스틸에서 원근 가설만 따로 판정할 수 있어야 하기 때문이다. 비트 구성 변경은 `storyboard-v4.md`에서 따로 제안한다.

**배제한 해석.** v2의 다이어그램 세계로 돌아가지 않는다. v3로 넘어온 이유("UI가 주인공인 기능 소구")가 여전히 유효하다.

**원근 제안 — "정면 2.5D + 오프닝에서만 3D 회전 한 번".**
- **기능 비트 ①–⑥**: 보드는 정면에 둔다. 회전 (rx, ry, rz) = (0, 0, 0)°.
  - 깊이는 층으로 만든다. 배경, 보드, 주인공 카드의 3층이다.
  - 떠오르는 카드는 scale 1→1.02, translateZ를 쓰고, 그림자는 오프셋 (8, 16)px에 블러 24px로 시작한다. 층 사이 시차는 8–16px로 시험한다.
  - 초점 밖 영역은 베일로 가린다.
  - 카메라는 팬과 줌만 한다. 헤드라인과 콜아웃을 읽는 동안에는 카메라가 멈춘다.
- **오프닝 한 번만** 입체를 쓴다.
  - 보드가 (rx, ry, rz) = (0, −40, 0)°로 보이며 측면, 두께, 분리된 그림자가 선명하게 드러난다.
  - 그다음 24–36f 동안 정면 (0, 0, 0)°로 회전하며 착지한다.
  - |ry|가 5–25° 구간을 지나는 시간은 12f 이내로 시험한다.
  - 과한 블러로 깊이 단서를 지우지 않는다. 착지 뒤에도 같은 보드로 알아볼 수 있어야 한다.
- **클로징**: 회전하지 않는다. 정면에서 축소와 타입 모핑으로 워드마크에 넘어간다.
- 원근을 유지하면서 translateZ를 쓰기 때문에, 정면이어도 Z가 있는 점의 화면 위치는 XY와 줌만으로 결정되지 않는다. 계산하면 원근 거리 2200, 깊이 180, 중심에서 500px 떨어진 지점에서 약 45px 차이가 난다. 그래서 **콜아웃 앵커는 Z를 포함한 같은 투영(`project.ts` 방식)으로 계산한다.**

**검토한 다른 원근 안.**
- **순수 2D** (원근 없음, 스케일과 층만): 가독성과 좌표 관리에 가장 유리하다. 다만 v3가 원했던 "무대 위의 제품"이라는 공간감을 전부 덜어낸다. 이번 안이 기각되면 다음 비교안이다.
- **전 구간 확실한 3D** (25–35° 무대): 공간이 일관된다. 다만 빽빽한 판정 패널을 크게 키우거나 재배치해야 한다. 가독성이 떨어진다는 것은 가설이지 확정 사실이 아니다.
- **아이소메트릭**: 사선 투영이라 한글 UI 텍스트가 기울어진다. 순위가 낮다.

**카피** (GPT와 의논한 결과, §8): 오프닝은 "Agent는 늘었는데 / 다음 일은 사람이 챙긴다 / 다음 일은 AI PM이 챙긴다"로 한다. 클로징 "다음 일은, PM이 챙긴다"는 유지한다.

## 4. 불변 조건

- 화면에서 UI 본문 텍스트는 20px 이상이다. 장면의 주인공 칩이나 배지는 36px 이상이다.
- 헤드라인은 읽을 수 있는 UI 텍스트와 겹치지 않는다. 콜아웃 칩은 다른 UI를 가리지 않고, 지시선은 칩까지 이어진다.
- 콜아웃 앵커의 투영 오차는 부상 전후 모두 1px 이하다.
- 머무는 포즈는 (0, 0, 0)°이거나 오프닝 시작 포즈 (0, −40, 0)°뿐이다. 5–25° 구간은 통과만 한다 (12f 이내).
- 헤드라인은 18자 이하다. 공백, 문장부호, 영문을 모두 포함해 센다 (`MOTION.md`). 과장어는 쓰지 않는다 (`DESIGN.md` 보이스).
- v3 공유 파일(`src/v3/**`)은 수정하지 않는다. v4의 차이는 `src/v4/`의 래퍼와 설정에 격리한다. v3 컴포지션 두 개(`StyleFrameV3`, `PitchV3`)는 계속 렌더된다.

## 5. 검증 계획

- `tsc --noEmit` 통과.
- 스틸 4장을 렌더하고 다음을 확인한다.
  - 텍스트 크기: 스틸에서 대표 텍스트 높이를 픽셀로 잰다.
  - 겹침과 가림: 눈으로 확인하고 라운드 로그에 기록한다.
  - 앵커 오차: 디버그 모드에서 3D 점과 2D 투영 점을 겹쳐 렌더해 확인한다.
- 카메라 설정을 코드에서 검사한다. 머무는 포즈가 위 두 가지뿐인지 본다.
- v3 회귀 검사.
  - `git diff`로 `src/v3/**`가 바뀌지 않았는지 확인한다.
  - v3 스틸 3장(SF1 r3, SF2 r8, SF3 r8)을 다시 렌더해 해시를 비교한다.
  - `PitchV3`에서 한 프레임을 렌더해 본다.
- **스틸 승인의 범위는 "룩 가설 승인"이다.** 회전 중 체류, 착지의 자연스러움, 떨림은 스틸로 증명되지 않는다. 승인 뒤 오프닝 전환만 담은 짧은 영상으로 따로 확인한다.
- 전체 영상 단계의 추가 검증 항목.
  - 비트별 헤드라인 노출 시간이 `max(1.2s, 단어 수/3 + 0.5s)` 이상인가.
  - 비트 ④에서 "결과 제출 → PM 확인 → 재지시 없이 다음 담당 시작"이 모두 화면 안에서 보이는가 (`intent.md` §8–9).

## 7. 미결정 사항

- 카피 최종 선택권은 사용자에게 있다. 추천안은 §8의 1위다.

## 8. 카피 (Codex와 의논한 결과)

글자 수는 공백, 문장부호, 영문을 모두 포함해 센다. v3 안 "잇는 건 이제 PM"이 어색한 이유는 두 가지다.
- "잇는 건"은 목적어가 없어서 무엇을 잇는지 한 번에 안 들어온다.
- 서술어 없이 끝난다.

**r0 후보 평가.**
- A, C: 2행이 서술어를 생략한다.
- A: 3행 어조가 클로징과 맞지 않는다.
- D: 1행이 19자라 기준을 넘는다. 2행과 3행도 명사로 끝난다.
- B: 원안 중 가장 적합했지만, "그 사이"보다 다음 작업을 직접 말하는 편이 낫다.

**채택안.** ②→③은 "사람이"만 "AI PM이"로 교체한다. 고정 어절은 "다음 일은"과 "챙긴다"다.

| 순위 | ① 문제 | ② 현재 | ③ 전환 (SF1b 헤드라인) | 글자 수 |
|---|---|---|---|---|
| **1 (채택)** | Agent는 늘었는데 | 다음 일은 사람이 챙긴다 | 다음 일은 AI PM이 챙긴다 | 11/13/16 |
| 2 | Agent는 늘었는데 | 일과 일을 사람이 잇는다 | 일과 일을 AI PM이 잇는다 | 11/13/16 |
| 3 | Agent는 늘었는데 | 맥락을 사람이 넘긴다 | 맥락을 AI PM이 넘긴다 | 11/11/14 |

클로징 "다음 일은, PM이 챙긴다"는 유지한다. 오프닝의 약속을 그대로 회수하고, "AI PM"은 오프닝에서 이미 소개됐다.

## 9. 통합 지점

- 새 컴포지션 `StyleFrameV4`를 `Root.tsx`에 등록한다. `PitchV4`는 스틸 승인 후에 만든다.
- 새 코드는 `src/v4/`에 둔다.
  - **새로 씀**: 정면용 Stage와 카메라(팬·줌·Z 층, 오프닝 회전 한 번), 콜아웃 래퍼(Z 포함 투영).
  - **import만 하고 수정하지 않음**: `src/v3/ui/*`(Board, Timeline, RightPanel, primitives, messages), `content.ts`, `tokens/video.ts`, `type/KineticHeadline.tsx`, `stage/project.ts`, `fx/CastShadow.tsx`, `fx/GlowField.tsx`.
  - v3 부품의 동작을 바꿔야 하면 v4에서 감싸거나 복사한다. 공유 파일은 고치지 않는다.

## 10. 의도 이탈 지점

- 사용자는 "처음부터 다시"라고 했다. 첫 스틸은 v3의 6비트와 목업 내용을 출발점으로 쓴다. 원근 가설을 따로 판정하기 위한 선택이고, 비트 구성은 재검토 대상으로 열어 둔다.
- 원근은 "정면 평면"과 "확실한 3D" 중 하나가 아니라 둘의 조합이다. 기능 비트는 정면이고, 오프닝 전환 한 번만 입체다.

## 개정 이력

- r0 (2026-09-28): 초안.
- r1 (2026-09-28): Codex Sol 설계 리뷰(REVISE) 반영.
  - 범위: 비트와 목업을 재검토 대상으로 열었다 (#1).
  - 회전: 오프닝 한 번 (0, −40, 0)°만 남기고, 클로징은 정면 축소로 바꿨다. 머무는 포즈 검사와 통과 시간 검사를 분리했다 (#2).
  - 투영: "정면이면 투영 오차가 사라진다"는 주장을 삭제했다. 앵커는 Z를 포함해 투영하고, 오차 1px 이하를 검증 항목에 넣었다 (#3).
  - 검증: 스틸 승인을 룩 가설로 한정하고, SF1을 회전 전·착지 후 한 쌍으로 만든다. 전환 영상과 비트 ④ 관찰 항목을 추가했다 (#4).
  - 회귀: v3 공유 파일은 수정하지 않고, v3 스틸 3장 해시와 두 v3 컴포지션 렌더를 확인한다 (#5).
  - 카피: 글자 수 세는 법을 명시하고 Codex 추천 1위를 채택했다 (#6).
  - 대안: 순수 2D를 비교안으로 추가했다.
