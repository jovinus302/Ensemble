# v4-pm 전체 모션 변경 명제

2026-09-28. 사용자 요청 「전체 모션 구현」에 따라 스틸 이후 제작을 시작한다. 이 명제는 구현 전에 기록한다. 기존 스틸 명제·검토는 `design-v4-pm.md`, 스타일 기준은 커밋 `4533823`의 9장이다. 제품 계획 기준 `36f6d7c`는 유지한다.

## 1. 확정된 의도

시청자가 57초 영상에서 PM이 사람과 Agent 사이의 다음 일을 챙기는 것을 시간 순서로 볼 수 있어야 한다. 중앙 오프닝 카피 2초, 착지 직후 PM 답장·지휘 중, 부족한 초안의 보완과 자동 인계, 필요할 때만 PM이 말하는 조율, 계획 변경의 전달·확인·결과 반영을 보여 준다. 완성 MP4를 렌더하고 검증한 뒤 현재 전용 브랜치에 커밋·푸시한다.

## 2. 해석과 가설 검토

**EXPERIMENT:** 승인된 룩을 재사용하는 프레임 기반 UI 모션이다. 실제 PM 백엔드나 실행 세션을 구현하는 것이 아니다. 고정된 시연 예시임을 UI에 표시한다. 오디오는 승인된 자료가 없으므로 이번에는 무음으로 납품한다.

스틸 9장을 단순 전환하는 안은 배제한다. 초안 부족·보완·인계 가능·제작 중을 서로 다른 화면 상태로 만들고, 조율에서는 휴가 발언 뒤 PM이 바로 말하지 않게 한다. 변경 메시지 전송, Agent 확인, 결과 대조를 시간으로 분리한다. 각 장면의 읽는 구간은 정지하며 카드 진입만 짧게 움직인다.

기존 스토리보드의 착지 답장 구간은 210–240f로 1초뿐이었다. 긴 답장을 읽을 수 있게 210–330f(4초)로 늘리고 기능 비트 길이를 조정한다. 전체 1710f는 유지한다. 새 구간: 팀 330–450, 계획 450–630, 맥락 630–810, 인계 810–1050, 조율 1050–1320, 변경 전달 1320–1530, 클로징 1530–1710. 헤드라인 유지 최소와 주요 인과 단계는 보존한다.

**가설 검토: SOUND.** 기존 카드·무대·투영·토큰에 프레임 상태와 진입을 추가하면 충분하다. 새 의존성이나 제품 정책은 필요 없다. 대표 프레임, 상태 전후의 DOM 관찰, MP4 디코딩과 시각 검토로 의도와 어긋남을 구분할 수 있다. 스틸 컴포지션은 별도로 보존해 비교한다.

## 3. 관찰 가능한 결과

- `PitchV4PM`: 1920×1080, 30fps, 1710f.
- `out/pitch-v4-pm.mp4`: 전체 57초 H.264 영상. 처음과 끝이 비지 않고 끝 워드마크는 최소 2초 정지한다.
- 오프닝 ③은 120–180f에 화면 중앙에서 완전히 정지한다. 180–210f에 한 번만 정면으로 회전하고, 210f부터 PM 답장과 사이드바 상태가 나타난다.
- 비트 ④: 부족한 초안 → 보완 r2 → PM 인계 가능 → 제작 시작. 각 단계 2초. 입력창은 비어 있고 상세 설계는 병행한다.
- 비트 ⑤: 휴가 발언 → 사람의 기한 질문 → PM의 기한 비교 → 디자이너 시간 약속 → 사용자의 범위 결정.
- 비트 ⑥: 계획 v2 → 변경 전송 → Agent 확인 → 수정 결과 내용 대조 → 반영 표시. 변경 확인만으로 결과 반영을 앞당기지 않는다. 옛 결제 결과는 인계 제외로 남긴다.
- B3의 결제 질문에 대한 김도윤 답변을 다음 비트로 가기 전에 표시해, 이후 결제 포함→제외의 인과가 끊기지 않게 한다.

## 4. 불변 조건

- `src/v3/**`, `src/v4/**` 변경 없음. 기존 v4 4장과 v4-pm 스틸 9장의 픽셀 결과를 보존한다.
- Noise 사용 없음. 보드는 기능 비트 전체에서 정면. 오프닝 회전 외 새 회전이나 카메라 흔들림 없음.
- 헤드라인 18자 이내. 지정 오프닝·클로징 원문 보존. 읽는 상태의 본문 ≥20px, 보조 ≥18px, 주인공 칩 ≥36px. 읽는 동안 헤드라인·콜아웃·UI 겹침 없음.
- 앵커는 카드 Z와 부상 비율을 포함해 투영하며 오차 ≤1px. 부상 중도 관찰한다.
- 회전 |ry| 5–25° 구간은 12f 이하로 통과한다. 기능 비트의 읽는 상태는 (0,0,0)°다.
- PM은 사람의 시간을 대신 약속하거나 범위 제외를 혼자 결정하지 않는다. 과장된 통계·자동 검증 약속 없음.
- 기존 스틸의 「결과 반영 대기」 상태는 변경하지 않는다. 전체 모션에서 별도의 결과 대조가 나온 뒤에만 「반영 확인」을 표시한다.

## 5. 검증 계획

| 항목 | 증거 |
|---|---|
| M1 형식·끝까지 렌더 | 타입 검사, 1710f 렌더 종료 0, MP4 스트림 정보(해상도·프레임 수·fps·시간), 실제 디코딩 |
| M2 인과·권한 | 단계별 렌더 DOM에서 보이는 대사·상태를 관찰. 제작 시작·변경 반영의 조기 표시가 없는지 경계 전후 확인 |
| M3 모션·읽기 | 중앙 홀드 60f의 렌더 비교, 회전 30f의 포즈와 중간 대표 이미지, 헤드라인 유지 시간, 마지막 60f 정지 |
| M4 가독성·좌표 | 읽는 단계와 진입 중 대표 프레임 측정, 부상 중·후 3D/2D 앵커 오차, 모든 주요 장면과 전환 구간을 직접 확인 |
| M5 회귀·범위 | v3/v4 소스 diff 없음, 기존 v4 4장과 v4-pm 9장 재렌더 SHA256 동일, 새 전체 모션만 등록, 지정 경로 커밋·push |

결함 수정은 한 라운드에 한 종류씩 기록한다. 실측 없이 자연스러움이나 제품 실동작 성공을 주장하지 않는다.

## 6. 실행 증거

구현 전. M1–M5 결과는 실행 후 채운다.

## 7. 미결정 사항

오디오·배포처는 지정되지 않았다. 기본 가로 16:9 무음 MP4로 만든다. 제품 MVP 범위의 잠정 결정은 기존 문서에 그대로 남긴다. 사용자 요청 자체가 전체 모션 착수 권한이므로 추가 승인 없이 진행한다.

## 8. 의도 이탈

영상 길이·주요 카피·룩·권한 경계의 약화는 없다. 개별 비트의 시작/끝 조정은 답장 가독성을 확보하기 위한 구현 해석이며 변경된 표를 스토리보드에도 기록한다.

## 개정 이력

- r0: 구현 전 명제. SOUND / EXPERIMENT. 이전 스틸 단계에서 전체 모션을 만들지 않았던 것은 당시 승인 경계였고, 이번 사용자 요청으로 해제되었다.
