# v4-pm 전체 모션 변경 명제

2026-09-28. 사용자 요청 「전체 모션 구현」에 따라 스틸 이후 제작을 시작한다. 이 명제는 구현 전에 기록한다. 기존 스틸 명제·검토는 `design-v4-pm.md`, 스타일 기준은 커밋 `4533823`의 9장이다. 제품 계획 기준 `36f6d7c`는 유지한다.

## 1. 확정된 의도

시청자가 57초 영상에서 PM이 사람과 Agent 사이의 다음 일을 챙기는 것을 시간 순서로 볼 수 있어야 한다. 중앙 오프닝 카피 2초, 착지 직후 PM 답장·지휘 중, 부족한 초안의 보완과 자동 인계, 필요할 때만 PM이 말하는 조율, 계획 변경의 전달·확인·결과 반영을 보여 준다. 완성 MP4를 렌더하고 검증한 뒤 현재 전용 브랜치에 커밋·푸시한다.

## 2. 해석과 가설 검토

**EXPERIMENT:** 승인된 룩을 재사용하는 프레임 기반 UI 모션이다. 실제 PM 백엔드나 실행 세션을 구현하는 것이 아니다. 고정된 시연 예시임을 UI에 표시한다. 오디오는 승인된 자료가 없으므로 이번에는 무음으로 납품한다.

스틸 9장을 단순 전환하는 안은 배제한다. 초안 부족·보완·인계 가능·제작 중을 서로 다른 화면 상태로 만들고, 조율에서는 휴가 발언 뒤 PM이 바로 말하지 않게 한다. 변경 메시지 전송, Agent 확인, 결과 대조를 시간으로 분리한다. 각 장면의 읽는 구간은 정지하며 카드 진입만 짧게 움직인다.

사용자 추가 지시 「채팅하는거처럼 올라가는거도 보여야해」를 구현 전에 반영한다. 메시지와 카드는 하나의 누적 대화에 쌓이고, 새 메시지가 하단에 들어오면 이전 메시지가 위로 밀린다. 20f 동안 새 메시지를 따라 스크롤하고 정지한다. 발언자는 매 메시지에 표시한다. 큰 계획 카드도 같은 타임라인의 메시지이며, 스크롤이 멈춘 뒤에만 부상한다. 위로 밀린 대화는 삭제하거나 장면마다 리셋하지 않는다. M2에는 새 메시지 전후의 이전 메시지 화면 Y 감소와 대화 누적도 확인한다.

기존 스토리보드의 착지 답장 구간은 210–240f로 1초뿐이었다. 긴 답장을 읽을 수 있게 210–330f(4초)로 늘리고 기능 비트 길이를 조정한다. 전체 1710f는 유지한다. 새 구간: 팀 330–450, 계획 450–630, 맥락 630–810, 인계 810–1050, 조율 1050–1320, 변경 전달 1320–1530, 클로징 1530–1710. 헤드라인 유지 최소와 주요 인과 단계는 보존한다.

**가설 검토: SOUND.** 기존 카드·무대·투영·토큰에 프레임 상태와 진입을 추가하면 충분하다. 새 의존성이나 제품 정책은 필요 없다. 대표 프레임, 상태 전후의 DOM 관찰, MP4 디코딩과 시각 검토로 의도와 어긋남을 구분할 수 있다. 스틸 컴포지션은 별도로 보존해 비교한다.

## 3. 관찰 가능한 결과

- `PitchV4PM`: 1920×1080, 30fps, 1710f.
- `out/pitch-v4-pm.mp4`: 전체 57초 H.264 영상. 처음과 끝이 비지 않고 끝 워드마크는 최소 2초 정지한다.
- 오프닝 ③은 120–180f에 화면 중앙에서 완전히 정지한다. 180–210f에 한 번만 정면으로 회전하고, 210f부터 PM 답장과 사이드바 상태가 나타난다.
- 비트 ④: 부족한 초안 → 보완 r2 → PM 인계 가능 → 제작 시작. 각 단계 2초. 입력창은 비어 있고 상세 설계는 병행한다.
- 비트 ⑤: 휴가 발언 → 사람의 기한 질문 → PM의 기한 비교 → 디자이너 시간 약속 → 사용자의 범위 결정.
- 비트 ⑥: 계획 v2 → 변경 전송 → Agent 확인 → 수정 결과 내용 대조 → 반영 표시. 변경 확인만으로 결과 반영을 앞당기지 않는다. 옛 결제 결과는 인계 제외로 남긴다.
- B3의 결제 질문에 대한 김도윤 답변을 다음 비트로 가기 전에 표시해, 이후 결제 포함→제외의 인과가 끊기지 않게 한다.

## 4. 불변 조건

- `src/v3/**`, `src/v4/**` 변경 없음. 기존 v4 4장과 v4-pm 스틸 9장의 픽셀 결과를 보존한다.
- Noise 사용 없음. 보드는 기능 비트 전체에서 정면. 오프닝 회전 외 새 회전이나 카메라 흔들림 없음.
- 헤드라인 18자 이내. 지정 오프닝·클로징 원문 보존. 읽는 상태의 본문 ≥20px, 보조 ≥18px, 주인공 칩 ≥36px. 읽는 동안 헤드라인·콜아웃·UI 겹침 없음.
- 앵커는 카드 Z와 부상 비율을 포함해 투영하며 오차 ≤1px. 부상 중도 관찰한다.
- 회전 |ry| 5–25° 구간은 12f 이하로 통과한다. 기능 비트의 읽는 상태는 (0,0,0)°다.
- PM은 사람의 시간을 대신 약속하거나 범위 제외를 혼자 결정하지 않는다. 과장된 통계·자동 검증 약속 없음.
- 기존 스틸의 「결과 반영 대기」 상태는 변경하지 않는다. 전체 모션에서 별도의 결과 대조가 나온 뒤에만 「반영 확인」을 표시한다.

## 6. 실행 증거

- **M1 — 형식·전체 렌더:** `npx.cmd tsc --noEmit` exit 0. `PitchV4PM` 1710f 렌더 완료. `out/pitch-v4-pm.mp4`는 H.264/yuv420p, **1920×1080, 30fps, 57.000초, 1710프레임**, 5,139,787바이트다. 전체 rawvideo 디코딩 exit 0. `v4-pm-motion/video.json`에 스트림·SHA256·디코딩 결과를 기록했다. 번들 ffmpeg의 기본 null 출력 인코더 부재로 최초 사후 검사가 실패했으며, 지원되는 rawvideo를 지정한 별도 `check-video.mjs`로 전체 검사를 완료했다.
- **M2 — 인과·권한·누적 채팅:** 54개 프레임의 렌더 DOM에서 상태 경계를 관찰했다. f869/r2 미표시 → f890/r2, f929/인계 전 → f950/인계 가능, f989/제작 전 → f1010/제작 중. 휴가·기한 질문 뒤 PM이 비교하며 사람 시간·범위 결정 후 계획을 바꾼다. f1412 전송 → f1445 Agent 확인·결과 대기 → f1478 수정 결과 → f1510 대조·반영 확인. 이전 보완 요청은 f830 y775 → f890 y555로 **220px 위로 이동**하고 새 답장이 쌓인다. 근거: `frames.json`, `verification.json`.
- **M3 — 모션·읽기:** 중앙 카피 f120/150/179 PNG 해시 동일, 단어 영역 중심은 화면 중앙 ±1px. 마지막 워드마크 f1650/1680/1709 해시 동일. 회전 중 |ry| 5–25°는 **11f**. 기능 비트 대표 포즈 모두 정면. 헤드라인 18자·유지 시간 조건 통과. 스크롤 후 f830/869와 f890/929 해시 동일로 읽는 구간 정지도 확인했다.
- **M4 — 가독성·좌표:** 본문 최소 **22.68px**, 보조 **19.91px**, 주인공 칩 높이 최소 **45px**, 부상 중·후 앵커 최대 오차 **0.01px**. DOM 넘침·콜아웃/로드맵 겹침 0건. 대표 비트와 전환 PNG를 열어 확인했고, 최종 MP4에서 추출한 f270·366·880·1010·1280·1510·1709도 직접 확인했다. f880은 상승 중인 이전 대화와 아래에서 들어오는 새 답장을 보여 준다. DOM만으로 발견하지 못한 3D 합성 누락은 이미지 검토 후 수정했다.
- **M5 — 회귀·범위:** 기존 v4 **4/4**, v4-pm **9/9** 스틸 재렌더 SHA256 동일(`regression.json`). `git diff --stat e1e77bf -- motion-remotion/src/v3 motion-remotion/src/v4`는 빈 결과다. 새 컴포지션과 코드는 v4pm에 추가하고 `Board`의 기존 스틸 경로를 보존했다. 지정 경로만 현재 전용 브랜치에 커밋·push한다. 원래 입력 브리프의 미추적 파일은 포함하지 않는다.

**구현 검토: PASS / EXPERIMENT.** (의도 충족) 전체 MP4·누적 채팅·PM 첫 행동·단계별 원인과 결과가 관찰된다. (의도 누락 검토) 입력 부족, 답변 대기, 결과 반영 대기, 옛 결과 인계 제외도 표현했다. 이 결과는 고정 시연의 구현이며 실제 제품 런타임의 동시성·복구 검증은 아니다. (의도 초과 없음) 백엔드나 제품 권한 정책을 추가하지 않았다. (프로젝트 정합성) PM 기준 `36f6d7c`와 기존 룩·카피·v3/v4 소스·스틸 픽셀을 보존했다. 이 판정은 시연 가설 구현의 검증이며 사용자 미감 승인이나 제품 결정 확정을 뜻하지 않는다.

전체 라운드·재현은 `log-v4-pm-motion.md`, 검토 재생 페이지는 `v4-pm-motion/index.html`이다.

## 7. 미결정 사항

오디오·배포처는 지정되지 않았다. 기본 가로 16:9 무음 MP4로 만든다. 제품 MVP 범위의 잠정 결정은 기존 문서에 그대로 남긴다. 사용자 요청 자체가 전체 모션 착수 권한이므로 추가 승인 없이 진행한다.

## 8. 의도 이탈

영상 길이·주요 카피·룩·권한 경계의 약화는 없다. 개별 비트의 시작/끝 조정은 답장 가독성을 확보하기 위한 구현 해석이며 변경된 표를 스토리보드에도 기록한다.

## 개정 이력

- r1 (2026-09-28, 구현 후): 54개 대표 프레임과 전체 MP4·디코딩·스틸 13장 회귀 증거를 기록했다. 기존 기대 결과를 약화하지 않고 회전 중 보드 클립, 로드맵 독립 합성, 클로징 순차 페이드로 겹침·누락을 수정했다. PASS / EXPERIMENT.

- r0 보충(구현 전): 사용자의 채팅 상승·누적 요구를 추가했다. 카드별 슬라이드 대신 누적 타임라인의 스크롤로 연결한다.

- r0: 구현 전 명제. SOUND / EXPERIMENT. 이전 스틸 단계에서 전체 모션을 만들지 않았던 것은 당시 승인 경계였고, 이번 사용자 요청으로 해제되었다.
