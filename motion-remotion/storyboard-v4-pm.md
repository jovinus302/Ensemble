# 스토리보드 — Ensemble v4-pm

1920×1080 · 30fps · 1710f = 57초. 변경 명제 선행 커밋 `6a5db2a`. PM 계획 기준 `36f6d7c`. 아래는 제작 설계이며 이번 납품은 스틸까지다.

## 1. 시간·카메라·카피

프레임 범위는 시작 포함·끝 제외다. P는 기능 비트 공통 정면 포즈 `(tx,ty,s)=(720,256,1.25)`, 회전 `(0,0,0)`, 화면 기준점 `(960,540)`, dz 0이다. 보드 상단은 y220. O는 승인된 v4 시작 포즈 `(720,450,0.8)`, 회전 `(0,−40,0)`, 기준점 `(880,520)`이다. 새 본문은 논리 18px 이상, 보조는 16px로 확대해 줌 1.25에서도 충분히 읽히게 한다. 주인공 카드는 Z 40·scale 1.02로 띄우고 자체 흰 표면을 둔다.

|---|---|---|---|---|
| 오프닝 문제 | 0–2 / 0–60 | Agent는 늘었는데 | O. 보드·측면·분리된 그림자. 읽는 UI 장면 아님 | O1 |
| 오프닝 현재 | 2–4 / 60–120 | 다음 일은 사람이 챙긴다 | O 유지, 화면 정면 타입 | O1과 같은 공간 |

각 비트 첫 12f는 카드 전환, 마지막 12f는 다음 초점 준비에 쓴다. 읽는 동안 카메라 정지. 헤드라인 유지 시간은 `max(1.2초, 단어 수/3+0.5초)` 이상으로 예약한다. 긴 카드 전체를 한꺼번에 읽게 하지 않고 아래 순서대로 한 덩어리씩 강조한다. 이번 스틸에서 노출 시간·전환 자연스러움은 입증하지 않는다. 오디오는 미정이다.

## 2. 장면별 대화·카드

공통 채널은 `# 고객반응-검증` 하나. 팀은 AI PM·김도윤(사람/결정권자)·이서연(사람/디자이너)·조사 Agent·프로토타입 Agent. 가상 인물이며 화면에 「시연 예시」를 표시한다. 실제 제품 기능을 실행한 녹화가 아닌 UI 목업이다. 사이드바에 다른 채널·DM을 넣지 않는다. 오른쪽은 Product State 검증률 대신 고정 로드맵이다.

### ① 같은 채널의 팀

목표: 「2주 안에 고객 반응 확인」. 팀 카드에 사람 두 명과 실행 Agent 두 명, PM을 구분한다. PM은 「대화 확인 중」으로 표시한다. Codex 실행 역할은 역할명으로 보이고 공급자 로고를 쓰지 않는다. 콜아웃 「한 채널의 팀」은 팀원 칩을 가리킨다.

### ② 가용 시간을 확인한 첫 계획

- 가용 시간 입력 예시: 김도윤 주 6시간, 이서연 주 8시간. 수치는 시연용 입력이며 성과 통계가 아니다.
- 사람이 목표·기한·자기 시간·PM 위임 범위를 처음 확인한다. 카드 하단 「목표·시간·위임 범위 · 당사자 확인」을 표시한다.
- 계획 v1: 조사 Agent의 자료 조사와 김도윤의 인터뷰는 함께 시작. 이서연의 초안은 문제 선택 후, 프로토타입은 초안 확인 후 시작.
- PM은 「역할과 가용 시간을 반영했어요. 조사와 인터뷰를 함께 시작해요.」
- 사람 시간을 모르는 상태에서는 날짜를 만들지 않는다. 초기 로드맵 예상 종료는 「입력 확인 중」으로 표시한다. 이후 ⑤에서 조건별 비교를 보여 준다.
- 콜아웃 「병렬로 시작」. 모든 변경에 사람 승인 버튼을 반복하지 않는다.

### ③ 필요한 맥락과 질문을 전달

- 「조사·인터뷰 → 이서연」 인계 카드: 목표, 결정 이유(고객 문제 ① / D1), 입력(조사 요약·인터뷰 기록), 사용 가능한 초안 부분과 남은 질문.
- Agent에서 온 질문 「결제 흐름도 만들까요?」를 사람에게 필요한 판단으로 전달. 아직 정해지지 않은 범위는 질문으로 남긴다.
- 세션 내부 사고·도구 로그·관련 없는 대화는 표시하지 않는다. 출처 링크 라벨 「결정 D1 · 원문 보기」를 둔다.
- 콜아웃 「결정 이유까지」. ③의 초안 v1은 입력 수정본 번호이며 계획 v1과 별개의 이름으로 표시한다.

### ④ 사람 결과에서 자동으로 이어지는 일

780–840f: 이서연의 초안 첨부. PM은 빠진 입력을 구체적으로 말한다: 「진입 화면이 빠졌어요. 초안에 추가해 주세요.」

840–900f: 이서연 「진입 화면을 보완했어요. 상세 설계는 이어서 할게요.」, 첨부 「흐름 초안 r2」.

900–960f: PM 「초안으로 제작할 수 있어요. 프로토타입 작업을 시작해요.」 / 「인계 가능」 칩.

960–1020f: 프로토타입 Agent 「흐름 초안 r2로 제작 중」. 이서연은 「상세 설계 진행 중」. 컴포저는 빈 상태. 대표 스틸에는 보완 이력, 인계 사유, 시작과 병행을 함께 남긴다. `checked` 의미만 보여 주고 검증 완료라고 하지 않는다. 콜아웃 「지시 없이 시작」.

### ⑤ 사람 대화 속 조율

| 순서 | 발언·행동 | PM의 근거 |
|---|---|---|
| 1 | 이서연 「목요일 휴가예요. 상세는 다음 주에 드릴게요.」 | 아직 사람끼리 말하는 중. PM 메시지 없음 |
| 2 | 김도윤 「그럼 제작도 늦어지나요?」 | 알려지지 않은 기한 영향이 다음 행동을 바꿈 |
| 3 | PM 「상세를 기다리면 2일 늦어요. 지금 초안으로 계속하면 기한 안이에요.」 | `pm-principles.md` 예시를 시연 조건으로 사용. 실측 성과가 아님 |
| 4 | 이서연 「초안으로 계속해요. 상세는 다음 주에 할게요.」 | 시간 약속은 당사자가 정함 |
| 5 | 김도윤 「결제 흐름은 이번 범위에서 빼죠.」 | 약속한 범위 변경은 권한자가 결정 |

대표 스틸은 선택적으로 펼친 같은 채널의 스레드다. PM이 강제로 방을 옮기거나 모든 발언에 답하는 장면이 아니다. 비교 카드에 「상세 후 제작 · 기한 +2일 / 초안으로 계속 · 기한 안, 재작업 가능」. 콜아웃 「필요할 때 한마디」.

### ⑥ 계획을 바꾸고 바뀐 담당자에게

- PM 「정리하면, 초안으로 제작 계속·결제 제외·상세는 다음 주예요. 계획에 반영했어요.」
- 계획 v1→v2: 제작 입력 「초안 r1 → 보완 r2」, 결제 「포함 → 이번 범위 제외」, 상세 「이번 주 → 다음 주(이서연 확인)」.
- 결정 근거: 「범위 · 김도윤 / 시간 · 이서연 / 계획 반영 · PM(위임 내)」. 사람 답변이 먼저 존재한 뒤 PM이 반영한다.
- 이서연은 변경 확인. 프로토타입 Agent는 「전송됨 → 변경 확인」, 실제 결과는 「반영 대기」. 이후 모션에서 결과 내용을 대조해야만 반영됨으로 바꾼다. 스틸은 확인과 완료를 합치지 않는다.
- 이전 계획의 결제 결과는 「이전 계획 결과 · 인계 제외」로 보존 표시. 영향 없는 조사 결과는 다시 실행하지 않는다. 정교한 되돌리기 버튼은 없다.
- 로드맵 v2는 상세 설계·제작이 병행 중임을 보여 준다. 변경 없는 사람에게 새 알림을 보내는 연출은 없다. 콜아웃 「바뀐 담당자에게」.

## 3. 스틸 검증과 승인 경계

O1·O2·B1–B6은 `StyleFrameV4PM`의 파일 props로 선택한다. UI 카드의 표현과 위계, 권한 구분, 가독성을 판단하기 위한 정지 화면이다. 스타일 프레임 승인 뒤에만 전체 모션 구현과 실제 노출 시간 검증을 진행한다. 회전·발언 시점·자동 실행의 인과는 스틸 승인만으로 검증되었다고 하지 않는다.
