## What the handoff failure means

The worker submitted a result three times. Judges first requested fixture/build/layout/report evidence, then explicit verification limits, then proof of buildability and 390/1440 layout. After two automatic revisions the native revision cap blocked the task. The full prompt was one handoff condition, and the harness waited for native `checked` status before running the external build/browser checks. Evidence the judge wanted therefore had not yet been generated by that sequence. Worker limitations also were not propagated into the judged result context. See [handoff diagnosis](handoff-diagnosis.json).

The highest-priority next improvement is the **verification-to-handoff sequence**: preserve the worker's limitations and feed authoritative build/browser results into final handoff review, or explicitly separate source-ready criteria from externally checked criteria. In parallel, the date oracle should compare equivalent dates/state, or the prompt must explicitly require a visible ISO date before another experiment. Add a negative control with genuinely wrong restored values. Do not change this run's frozen inputs or relabel its failures while making those future repairs.

Worker cumulative totals are 488,643 tokens for Ensemble and 146,184 for direct; Ensemble's five recorded PM/judge responses add 163,178 tokens. The observed combined Ensemble total is 651,821. Cached input is already a subset of input, and reasoning is already a subset of output; do not add either twice. These are reported token counts with cache/repeated-context semantics, not dollar costs or exact hidden API-call counts. Primary reports retain null complete usage/cost/API-count fields.

This is **n=1, one provider, one task**, fixed order, with uncontrolled shared host/provider load. Direct and Ensemble also initialize their thread/workspace in a slightly different order, documented before execution. The evaluator and handoff sequence limitations prevent a clean overall quality/speed superiority conclusion. The useful finding is where this configured pipeline loses completion evidence, not that one system is universally better.
