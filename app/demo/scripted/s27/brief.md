## 전달할 메시지

앙상블은 팀의 컨텍스트, 도구, 의사결정과 결과물을 연결해 사람과 에이전트가 협업을 이어갈 수 있게 하는 **공유 업무 기반**이다. 협업은 미팅·슬랙 등 팀이 일하는 채널에서 시작하고, 근거·결정·결과물은 앙상블에 연결되어 다음 작업에 쓰인다.

보여줘야 할 순간(해자 가설):
- **경험적**: 채널·담당자가 바뀌어도 아무도 배경을 다시 설명하지 않는다. 에이전트가 기존 결정과 최신 결과물을 스스로 이어받는다.
- **기술적**: 대화·근거·결정·도구 실행·결과물의 연결 관계가 보존되고, 결과물의 버전·출처·결정 근거를 추적할 수 있다.
- **축적**: 결정 이력과 피드백이 다음 작업의 자산이 된다(v1.1이 법무 피드백과 v1을 함께 이어받음).

## 허브에 미리 있던 공유 자료 (source, origin `hub`)

- `src-guide` **S27 브랜드 가이드 v3** — 톤: 자신감 있되 과장 없음. 금지: 경쟁사 비교, "최초/유일" 등 최상급 단정.
- `src-s26` **S26 캠페인 성과 리포트** — 숏폼 영상(15초) CTR이 정적 배너 대비 높았고, 2030 세그먼트 전환이 가장 좋았음. 수치는 "리포트 기준"으로만 인용(구체 숫자는 가상 표기 허용, 실제 데이터라고 주장하지 않음).
- `src-spec` **S27 제품 스펙 시트** — 나이트 포트레이트, 배터리 사용시간(조건부 수치).
- `src-legal` **광고 표기 체크리스트** — 수치 표기 시 측정 조건 각주 필수, 엠바고 전 가격 언급 금지.

## 단계별 흐름 (발표자 클릭 = beat)

### 1. 미팅에서 결정 — 녹스 미팅 "S27 캠페인 킥오프" (10/1)
- 하린·준호·서아가 방향을 논의. 앙상블 에이전트가 미팅에 참여해 있음.
- 결정 3건이 생긴다:
  - `d-message` 핵심 메시지 = **"밤에도 선명한 인물 사진"(나이트 포트레이트)**. 근거: `src-spec`, `src-s26`.
  - `d-target` 타깃·채널 = **2030, 메타 피드 + 유튜브 숏폼 우선**. 근거: `src-s26`.
  - `d-constraint` 제약 = **경쟁사 비교 금지, 수치엔 측정 조건 각주, 가격은 엠바고(10/20) 전 언급 금지**. 근거: `src-guide`, `src-legal`.
- 앙상블이 미팅 끝에 capture 라인: "결정 3건을 앙상블에 기록했고, 근거 자료 4건과 연결했습니다."

### 2. 슬랙에서 요청 — `#s27-launch` (10/2)
- 준호: "@Ensemble 킥오프 결정대로 메타 피드 소재 3종이랑 숏폼 스크립트 하나 초안 부탁해요."
- **준호는 배경을 다시 설명하지 않는다.** 앙상블이 응답에서 스스로 이어받은 것을 밝힌다: 킥오프 결정 3건, 브랜드 가이드 v3, S26 리포트. "가격은 엠바고라 넣지 않겠습니다."
- `req-draft` 요청 노드 생성.

### 3. 맥락으로 드래프트
- 도구 실행 2건(`tool_run`): `tool-s26` "S26 성과 리포트 조회 — 숏폼 포맷·2030 반응 문구 추출", `tool-check` "브랜드·법무 표기 검사 — 금지 표현 0건, 각주 필요 1건 처리".
- 카피 Agent가 `art-v1` **S27 사전예약 소재 v1.0**을 만든다: 메타 피드 A/B/C + 숏폼 스크립트(15초). 각 섹션 `grounds`에 근거 노드 id.
- 앙상블이 `#s27-launch`에 artifact 카드로 게시(근거 칩 포함).

### 4. 근거·결정 연결 확인 — 앙상블 허브
- 허브 화면 전환. `art-v1` 선택 → 상류 추적: 요청 ← 결정 3건 ← 공유 자료, 사용한 도구 실행.
- 발표 포인트: "이 문장이 왜 이렇게 쓰였는지"를 섹션 단위로 결정·자료까지 따라갈 수 있다.

### 5. 다른 팀원이 이어서 수정 — `#brand-review` (10/3), 다른 채널·다른 사람
- 민재(법무) 피드백 `fb-legal`: "B안 '하루 종일 가는 배터리'는 측정 조건 각주가 있어야 하고, '압도적'은 최상급이라 빼 주세요."
- 서아(브랜드) 피드백 `fb-brand` + 요청: "@Ensemble 위 법무 의견 반영하고 톤 조금 더 따뜻하게. 숏폼은 첫 3초에 인물 클로즈업으로."
- **서아는 v1이 어디 있는지, 킥오프에서 뭘 정했는지 설명하지 않는다.** 앙상블이 최신 버전(v1.0)과 킥오프 결정을 스스로 찾아 이어받는다.
- `art-v11` **v1.1** 생성: `supersedes: art-v1`, changes 목록(각주 추가, 최상급 제거, 톤 조정, 숏폼 오프닝 변경). 결정 3건은 그대로 유지됨을 명시.
- 앙상블이 `#brand-review`에 v1.1 카드 게시 + 원래 요청자 준호에게 `#s27-launch` 스레드로 "v1.1로 갱신됨" 알림(같은 맥락 연결).
- 마지막 beat: 허브에서 `art-v11` 선택 → v1.0과의 변경점, 피드백 2건, 결정 3건이 모두 연결된 그래프. 이어서 해자 가설 지표와 구현 현황 표.

## 금지·주의

- 실제 회사·제품 로고, Slack·녹스 상표 디자인을 흉내 내지 않는다. 화면은 중립적인 "팀 메신저"/"화상 미팅" 스타일에 채널명과 "(시뮬레이션)" 표기.
- 지표 숫자를 측정 결과처럼 쓰지 않는다. 모든 지표 옆에 "시나리오 가정".
- 데모 내 카피 문구는 그럴듯하되 가상의 문구다.
