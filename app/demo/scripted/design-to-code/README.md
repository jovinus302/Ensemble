# 디자인→개발 협업 데모

확인 기준: **2026-10-05, main `605521b` (PR #68 병합)**. 경로는 `/demo/design-to-code`이며 실행 방법과 다른 데모와의 차이는 [데모 안내](../../README.md)를 참고한다.

## 보여주는 흐름

이지윤(UX)과 김상성(개발)이 만료된 로그인 링크 화면을 보며 대화한다. PM은 대화를 근거로 복구 방향을 제안하고, 두 사람이 합의한 뒤 각자의 Agent와 만든 결과를 공유해 다음 작업으로 연결한다. 화면의 고정 관점은 김상성이며 버튼에는 현재 역할이 표시된다.

1. **방향과 제약 합의:** 기존 로그인 화면으로 돌아가기 또는 60초 안내 후 링크 재발송을 고른다. 이메일 가리기를 추가하거나 다른 경로를 다시 논의할 수 있다. 이지윤과 김상성의 동의가 모두 있어야 진행한다.
2. **UX 초안 공유:** 개인 초안을 준비해도 공유하기 전에는 팀의 최신 결과가 바뀌지 않는다. 공유된 초안이 Coding Agent의 입력이 된다.
3. **구현과 QA:** 공유한 구현을 QA에 넘긴다. 포커스 복구 누락 사례에서는 해당 항목만 보완하고 다시 검사하는 흐름을 보여준다.
4. **사람 검토와 인계:** QA 결과 뒤 사람이 검토한다. 버튼 문구를 고치라는 요청은 기존 결정·동작을 유지하며 해당 문구만 바꾼다. 사람 승인 후 모바일 담당에게 인계한다.

이전 결과나 중복 클릭이 현재 인계를 진행시키지 않도록 버전과 실행 회차를 확인한다. 취소·초기화·내부 이전/다음 이동은 진행 중 콜백을 무효화한다. 이 규칙은 데모의 상태 전이이며 실제 서버의 권한·영속성 계약은 아니다.

## 시연의 경계

- 유한한 답변 선택지, 고정 데이터, 역할을 바꿔 누르는 동의 버튼을 사용한다. 실제 사용자 인증이나 PM·Agent 추론은 없다.
- 준비 타이머가 사람 대신 동의하거나 초안을 공유하지 않는다.
- 로그인 이동·메일 재발송은 화면 예시다. 메일을 보내지 않으며 60초 표시는 실제 경과시간 기반 제한이 아니다.
- QA 결과는 시나리오 예시다. 미리보기의 포커스 동작은 확인할 수 있지만 실제 작업자의 산출물을 실행 검증하는 시스템은 아니다.
- 새로고침하거나 경로를 떠나면 새 시연을 시작한다. 원장·DB에 저장하지 않는다.
